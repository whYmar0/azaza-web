# fat_review.md — самопроверка на «толстые» функции

Реальный аудит текущего кода . Проверка автоматическая, не
на слово: `grep` по `core/*.py` подтверждает, что там нет ни одного
импорта Django (см. коммит с этим файлом).

| # | Проблема | Что не так | Куда убрать | Есть ли у нас? |
|---|---|---|---|---|
| 1 | Расчёт написан прямо внутри view/API-функции | Нельзя протестировать без Django и HTTP | В `core/` | Нет — `web/api.py::create_task` — 2 строки, только вызов `services.create_task`. Проверка: `core/tests/` (8 тестов) гоняются без Django вообще. |
| 2 | Функция ядра сама читает/пишет в БД | Ядро нельзя протестировать без базы; нарушает AGENTS.md | В `web/services.py` | Нет — `core/solver.py` и `core/schemas.py` не импортируют Django (проверено `grep`, не на слово). |
| 3 | Валидация вперемешку с расчётом | Легко забыть проверку; нельзя тестировать отдельно | В `core/schemas.py`, до вызова функции | Нет — `SudokuParams` (валидация) и `solve()` (расчёт) — разные файлы, `solve()` про pydantic вообще не знает. |
| 4 | Расчётная функция сама меняет статус/пишет прогресс наружу | Функция перестаёт быть чистой | В `web/services.py` | Нет — `solve(grid)` возвращает строку и всё, статус (`Task.status`) меняет `web/services.py::_run`, а не `core/solver.py`. |
| 5 | Одна функция валидирует + считает + сохраняет + формирует ответ | Нарушен принцип единственной ответственности | Разбить по слоям | Пограничный случай — см. ниже |

## Пункт 5 подробнее

`web/services.py::_run` действительно делает несколько вещей подряд:
меняет статус на `running`, вызывает `core/solver.solve`, сохраняет
`PuzzleResult`, меняет статус на `done`/`error`. Формально это несколько
шагов в одной функции.

Но это осознанно, а не забытая толстая функция: `_run` — это и есть
слой оркестрации (`web/services.py`), которому по архитектуре разрешено
знать и про `core/`, и про Django ORM одновременно (см. ADR-001). Что он
**не** делает — то, что было бы реальной проблемой:
- не валидирует вход (это уже сделано в `core/schemas.py` до вызова);
- не формирует HTTP-ответ (это `web/api.py`);
- не содержит логики решения судоку (это `core/solver.py`).

## Итог

На 4 сентября 2026 все 5 пунктов чек-листа пройдены по факту, не в
теории. Если в `core/` появится новая функция (например,
`core/generator.py`) — проверять по этой же таблице перед коммитом.
