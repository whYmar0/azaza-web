# Sudoku Generator & Solver — идея проекта

## Идея

Веб-сервис-генератор судоку с гарантией единственного решения. Пользователь
выбирает уровень сложности (easy / medium / hard) и получает головоломку, у
которой точно есть ровно одно решение — не ноль и не несколько. Сервис также
умеет решать и валидировать произвольные сетки судоку 9×9.

## Рамка: вход → тяжёлая функция → выход

**Вход.** Уровень сложности (easy / medium / hard) — либо готовая сетка 9×9
(81 ячейка, 0 = пустая клетка) для решения или проверки.

**Тяжёлая функция.** Составление судоку — это, по сути, решение пустой сетки
по правилам (в каждой строке, столбце и блоке 3×3 цифры 1–9 без повторов).
При удалении клеток из полной сетки запускается перебор (backtracking),
проверяющий, что решение остаётся единственным. Для hard-уровня, где
подсказок минимум, перебор реально считает секунды, а не миллисекунды.
Решать эту задачу можно двумя способами:

- **Оптимизированный backtracking** — constraint propagation (naked/hidden
  singles) + эвристика MRV. Метрика ценности — минимальное время выполнения.
- **Итеративный (anytime) алгоритм** — local search / simulated annealing:
  решение с каждой итерацией становится лучше (число конфликтов
  уменьшается), пока не станет верным; прогресс можно показывать в реальном
  времени через опрос статуса задачи.

**Выход.** Сгенерированная головоломка, полное решение, время выполнения
(мс) и метрика сложности (число итераций / шагов перебора).

## API

| Метод | Путь                        | Тело запроса                                                    | Код ответа | Что возвращает |
|-------|-----------------------------|------------------------------------------------------------------|------------|-----------------|
| POST  | `/api/sudoku/generate`      | `{difficulty: "easy"\|"medium"\|"hard", algorithm: "fast"\|"progressive"}` | `202`      | `task_id` |
| GET   | `/api/tasks/{task_id}`      | —                                                                  | `200` / `404` | `status`, `elapsed_ms`, `iteration`, `conflicts_left` |
| GET   | `/api/tasks/{task_id}/result` | —                                                                | `200` / `404` | сгенерированная сетка, решение, `elapsed_ms`, `iterations`, `algorithm` |
| POST  | `/api/sudoku/solve`         | `{grid: [81 int]}`                                                | `200` / `400` | решение, `unique: bool`, `solutions_found`, `elapsed_ms` |
| POST  | `/api/sudoku/validate`      | `{grid: [81 int]}`                                                | `200` / `400` | `valid: bool`, `conflicts: [{row, col, reason}]` |

Генерация асинхронная (`202` + опрос статуса), потому что проверка
единственности решения — та самая долгая функция, требующая фоновой
обработки. `solve` и `validate` — синхронные (`200`), они выполняются быстро.

## Технический стек

Python 3.14, Django 5.x, Django Ninja, pydantic, pytest, ruff.

## Архитектурные ограничения

1. `core/` не импортирует Django, не ходит в БД и HTTP — там только логика
   судоку (генерация, решение, проверка).
2. `views` и API не содержат бизнес-логики — только вызывают
   `web/services.py`.
3. Вход валидируется pydantic-схемой до расчёта. Никакого `eval`.
4. Секреты — только в `.env`.
