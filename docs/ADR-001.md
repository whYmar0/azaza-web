# ADR-001: Контекст проекта

## Статус
Принято и реализовано.

## Контекст
Команда из четырёх человек, курс «Архитектура и проектирование
веб-приложений» . Выбранная тема —
сервис-генератор судоку с гарантией единственного решения: пользователь
задаёт параметры, ядро генерирует и/или решает головоломку.

Стек фиксирован для стартового проекта курса (AGENTS.md): Python,
Django, Django Ninja, pydantic, pytest, ruff. Ключевое архитектурное
ограничение — вычислительное ядро (`core/`) не должно зависеть от
Django, БД и HTTP.

## Решение
Единый контракт на два входа: `core.schemas.SudokuParams` (`mode`,
`grid`, `difficulty`, `seed`) используют одновременно `web/forms.py`
(страница для человека) и `web/api.py` (Django Ninja, для программы) —
поля не дублируются в двух местах с риском разойтись по именам.

`core/` (`solver.py`, `schemas.py`) не содержит ни одного импорта Django
— проверено: тесты в `core/tests/` запускаются без поднятого Django
и без базы данных. Побочные эффекты (сохранение в БД, HTTP-ответы,
статус фоновой задачи) — только в `web/services.py`.

## Последствия
- Новое поле входа — правка в одном месте (`core/schemas.py`), форма и
  API получают его синхронно.
- Ядро тестируется в изоляции — `pytest core/tests/` не требует
  `DJANGO_SETTINGS_MODULE` и БД (в отличие от `tests/test_api.py`, где
  нужен `pytest-django`).
