# ADR-003: Доступ — вход на сайт и «только свои задачи»

## Статус
Принято и реализовано (пара 13, 01.10).

## Контекст
До пары 13 сервер не спрашивал, кто пришёл. Номера задач идут подряд
(1, 2, 3…), поэтому любой — даже без входа — открывал чужую задачу по
номеру на странице (`/tasks/N/`), в API (`/api/tasks/N`) и её результат
(`/api/tasks/N/result`). Проверено преподавателем 30.09: аноним открывает
чужую задачу и результат — `200`.

Нужны оба вопроса сервера:
1. **Кто ты?** (аутентификация) — вход на сайт, дальше в каждом запросе
   `request.user`.
2. **Что тебе можно?** (авторизация) — у задачи есть владелец, задачу
   ищем по номеру **и** владельцу.

Только вход — мало: вошедший Пользователь 2 всё равно открыл бы задачу
Пользователя 1. Спрятать номер (сделать длинным и случайным) — тоже не
решение: номер можно подсмотреть или угадать. Сервер должен проверять
«эта задача — твоя?» при каждом запросе.

## Решение
Три шага, каждый в своём слое:

1. **Владелец** — `web/models.py`: `Task.owner = ForeignKey(AUTH_USER_MODEL,
   on_delete=CASCADE, null=True, blank=True, related_name="tasks")`,
   миграция `web/migrations/0003_task_owner.py`. Пользователи — встроенная
   таблица Django; пароли хранятся только как хэш (pbkdf2 + соль), сами мы
   пароли не храним и не сравниваем.
2. **Вход** — готовые страницы Django (`accounts/` →
   `django.contrib.auth.urls`), шаблон `web/templates/registration/login.html`,
   `LOGIN_URL`/`LOGIN_REDIRECT_URL` в настройках, `@login_required` на
   странице формы и странице задачи. API — `NinjaAPI(auth=django_auth)`:
   та же cookie сессии, что и у сайта.
3. **Фильтр** — `web/services.py`: `create_task(user, …)` записывает
   `owner=user`, `get_task(user, task_id)` ищет
   `filter(id=task_id, owner=user)`. Это **единственное** место правила:
   его вызывают и страница (`views.task_detail`), и API (`task_status`,
   `task_result`). Отдельной проверки для API нет и не нужно.

### Чужая задача — 404, а не 403
Оба ответа закрывают доступ, но `403 «доступ запрещён»` выдаёт лишнее:
Пользователь 2 узнаёт, что задача № 7 существует, и перебором — сколько
задач в системе всего. С `404` для Пользователя 2 чужая № 7 неотличима от
несуществующей № 999. Технически это получается само: чужая задача →
`get_task` возвращает `None` → тот же `404`, что уже был для
несуществующего номера (`api.py`, `if task is None: raise Http404`).

## Последствия
- **Если убрать `owner=` из фильтра в `services.get_task`** — дыра
  открывается сразу и на странице, и в API (одно место правила).
  Проверено: на такой копии кода `tests/test_access.py` падает с
  `assert 200 == 404` — Пользователь 2 снова видит чужую задачу.
- **Аноним в API: `401`, но голый `curl` без CSRF-токена — `403`.**
  `django_auth` (Django Ninja 1.7) для небезопасных методов (`POST`)
  сначала проверяет CSRF-токен и только потом «кто вы». Из `/api/docs`
  (Swagger) токен подставляется сам → аноним получает `401
  Unauthorized`; запрос без токена отсекается раньше — `403 CSRF check
  Failed`. Оба ответа — отказ, ни один не `200`. CSRF-проверку **не
  отключаем**: она защищает вошедшего пользователя от подделки запроса
  с чужого сайта. В тестах Django-клиент CSRF не проверяет, поэтому там
  аноним сразу получает `401`.
- **Старые задачи без владельца** (`owner = NULL`, созданы до миграции)
  не видны никому, кроме админки. Это сознательно: приписать их
  кому-то задним числом нельзя, а показывать всем — та же дыра.
- **Регистрации нет**: пользователей заводит админ (`createsuperuser`,
  `/admin/`). Для курсового проекта достаточно; страница регистрации —
  отдельное решение, если понадобится.
- **Список задач** (на паре 13 его не было) появился на паре 14 — блок
  «Мои задачи» на главной: `services.list_tasks(user)` →
  `Task.objects.filter(owner=user)`. Без фильтра он выдал бы все задачи
  всех без всякого перебора; проверено тестом
  `test_task_list_shows_only_own_tasks`. `GET /api/tasks` (список в API)
  по-прежнему нет.
- Старые тесты сайта и API после входа покраснели (аноним → `302` на вход
  / `401`) — это правильное новое поведение, а не поломка. Они переведены
  на вошедшего пользователя (фикстура `auth_client` в `tests/conftest.py`).

## Рассмотренные варианты — сводно (дополнено 02.10, пара 16)

| Вариант | Почему нет |
|---|---|
| Только вход, без владельца у задачи | вошедший Пользователь 2 открывает задачу Пользователя 1 по номеру |
| Длинный случайный номер задачи вместо проверки | номер можно подсмотреть или переслать; сервер по-прежнему не знает, чья задача |
| Чужая задача — `403` | выдаёт, что задача существует, и позволяет перебором узнать, сколько задач в системе |
| Проверка владельца в каждой функции страницы и API отдельно | три места вместо одного: забыли в одном — дыра |
| Отдельный токен для API | второй способ входа и место, где хранить токены; cookie сессии уже есть |
| **Вход Django + владелец + фильтр в одном сервисе, чужая — `404`** | выбрано |
