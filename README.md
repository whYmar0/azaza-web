# Sudoku Service

Веб-сервис-генератор судоку с гарантией единственного решения. Формат сетки
— строка из 81 символа (`1`-`9` и `.` для пустой клетки). Один контракт на
два входа: страница (для человека) и `/api/tasks` (для программы).

## Идея

Подробно, с обоснованием архитектуры («рамка») — в `docs/idea.md`.

## API

`POST /api/tasks` — `{"name": "...", "params": {"mode": "solve"|"generate", "grid": "...", "difficulty": "...", "seed": ...}}` → `202` + `{"id": ...}`.
`GET /api/tasks/{id}` — статус (`queued`/`running`/`done`/`error`).
`GET /api/tasks/{id}/result` — результат, когда `status == done`.
Полная документация с примерами запросов — `docs/api.md`; интерактивно —
`/api/docs` (Swagger, автогенерация Django Ninja).

## Структура проекта

- `core/` — вычислительное ядро. Не импортирует Django, не ходит в БД и HTTP.
  - `core/solver.py` — решатель (backtracking + MRV).
  - `core/generator.py` — генератор головоломок: строит полную сетку,
    удаляет клетки по одной, после каждого удаления проверяет
    единственность решения через `solve()` (limit=2); при фиксированном
    `seed` результат воспроизводим.
  - `core/schemas.py` — `SudokuParams`: pydantic-валидация входа ДО расчёта
    (длина, допустимые символы, паттерны mode/difficulty, отсутствие дублей
    в строках/столбцах/блоках).
  - `core/tests/` — 16 тестов на чистую логику (эталоны + схема + генератор).
- `web/` — Django-слой:
  - `web/models.py` — `Task` (заявка, с полями `name`/`kind`/`status`/`params`/`error`), `PuzzleResult`.
  - `web/services.py` — единственная точка входа для views/API в `core/`; фон — поток, статус пишет прямо в `Task.status`; время расчёта — реальное, через `time.perf_counter()`.
  - `web/api.py` — тонкий Django Ninja роутер, почти не меняется.
  - `web/forms.py` — форма с теми же именами полей, что в `core/schemas.py`.
  - `web/views.py` — `index` принимает `POST`, создаёт задачу и
    перенаправляет на `task_detail`; `task_detail` показывает статус,
    результат или ошибку.
  - `web/templates/` — страница с формой (`index.html`) и страница
    результата (`task_detail.html`, автообновление, пока задача считается).
- `tests/test_api.py` — тест уровня API (нужен Django, поэтому отдельно от `core/tests/`).
- `tests/test_site.py` — путь через сайт: форма → редирект → задача `done` с известным
  решением и `elapsed_ms > 0`; некорректная сетка не создаёт задачу.
- `docs/` — идея (`idea.md`), API-контракт (`api.md`), ER-схема
  (`ER.png`), архитектурные решения (`ADR-001.md`, `ADR-002.md`),
  самопроверка архитектуры (`fat_review.md`).

## Реперная точка 21.09

Требование чекпоинта: путь «форма → расчёт → результат» должен работать
целиком, время расчёта — настоящее, а не заглушка, и должен быть
содержательный следующий шаг (генератор с проверкой единственности).

- **Вход:** опубликованная головоломка судоку, 81 символ,
  `53..7....6..195....98....6.8...6...34..8.3..17...2...6.6....28....419..5....8..79`
  (классический пример, широко публикуется вместе с решением, в т.ч. на
  Wikipedia).
- **Ожидаемый выход:** единственное решение
  `534678912672195348198342567859761423426853791713924856961537284287419635345286179`.
- **Откуда известен ответ:** решение опубликовано вместе с условием
  независимо от нашего кода — мы не генерировали пару вопрос/ответ сами
  (см. также `core/tests/test_reference_puzzle.py` — вторая, более сложная
  эталонная головоломка, Arto Inkala, 2012, с ответом, сверенным по
  независимому источнику).
- **Алгоритм:** `core/solver.py` — backtracking с MRV-эвристикой
  (наименее заполненная клетка выбирается первой), поиск до двух решений
  (`limit=2`) для проверки единственности без лишнего перебора.
- **Генератор (следующий шаг, реализован):** `core/generator.py` строит
  полную валидную сетку, затем удаляет клетки по одной в порядке,
  зависящем от `seed`; после каждого удаления проверяет единственность
  тем же `solve()` и откатывает удаление, если решений стало больше
  одного. Эталон для генератора — `core/tests/test_generator.py`:
  фиксированный `seed=42`, тест проверяет и воспроизводимость (тот же
  seed → тот же результат, в том числе в разных процессах — как после
  рестарта сервера), и единственность решения.
- **Ограничение текущей версии:** нет защиты от параллельной записи при
  нескольких одновременных задачах (SQLite + threading, см. ADR-002);
  генератор не гарантирует ровно фиксированное число подсказок для
  каждой сложности (только не больше целевого — если разрежение
  останавливается раньше из-за потери единственности, подсказок может
  быть немного больше цели).

## Запуск с чистой машины

```bash
git clone <url> sudoku-service && cd sudoku-service
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Тесты: `pytest`. Админка: `http://127.0.0.1:8000/admin/`. API-документация:
`http://127.0.0.1:8000/api/docs`.

## Архитектурные принципы

1. `core/` не зависит от Django, БД и HTTP.
2. Views и API не содержат бизнес-логики — только вызывают `web/services.py`.
3. Вход валидируется pydantic-схемой до расчёта. Никакого `eval`.
4. Секреты — только в `.env`.
